ANEXO · CRONOLOGÍA

The Ralph loop · jul 2025 · Geoffrey Huntley

while true; do
    opencode run -m opus-4-5 "$PROMPT"
done

ralph.sh — ghuntley.com/ralph · «full hands-off vibe coding» · «it requires faith — and a belief in eventual consistency»

WHAT IT DOES

Feed the same spec to a headless agent, in an infinite loop. It iterates against tests and lint until it converges — unattended.

THE MEME 🍩

Named after Ralph Wiggum, The Simpsons' simpleton. Your agent is Ralph — sometimes brilliant, often dumb; you tolerate it and correct it.

WHY IT MATTERS

A bash loop made self-running agents mainstream — one step away from factories.

Ralph Wiggum — the namesake

⏱ 8.5–10'. ANEXO de la cronología, en inglés (guiño al meme). El bucle: spec en PROMPT.md + opencode headless + bash infinito (versión de Huntley con claude-code). EL REMARQUE: «a partir de Ralph, la gente buscó agentes que corran solos — el loop auto se volvió mainstream. De aquí a las factories hay un paso». Matiz honesto: Devin (2024) ya era autónomo; Ralph lo hizo accesible a cualquiera. Citas: «full hands-off vibe coding» y «faith + eventual consistency».

Software Development Life Cycle — el ciclo de vida con el que se fabrica software:

01

02

03

05

Un ciclo: lo que aprendes en producción vuelve a la idea. Y cada vuelta puede durar semanas… o minutos.

⏱ 10–11'. Para no programadores: «el SDLC es la cadena de montaje del software — de la queja del usuario al despliegue y vuelta». Presenta las 6 palabras que usaremos toda la charla. No detenerse: el dibujo real viene ahora.
ESTACIÓN 2 · EL SDLC — 1/4

Fase 1 · La demanda y la dirección

USERS → quejas · feature requests
quejas / requests → CEO / Vision LOOP #2
CEO / Vision → Product Managers
Product Managers → Engineers
Engineers → stuff to do
⏱ 12–13.5' · FASE 1: la demanda y la dirección. Todo empieza en USERS (quejas y peticiones) y sube por LOOP #2 hasta CEO/Vision; de ahí baja: PMs deciden qué hacer, Engineers lo apuntan como stuff to do. Aún no hay código: es la mitad «humana» de la fábrica.
ESTACIÓN 2 · EL SDLC — 2/4

Fase 2 · El build

stuff to do → someone builds the thing
someone builds → automated testing
someone builds → manual testing (browser)
⏱ 13.5–15' · FASE 2: el build. Someone builds the thing — nota el «someone»: en 2022 era una persona. Dos válvulas de calidad: tests automáticos y prueba manual en navegador.
ESTACIÓN 2 · EL SDLC — 3/4

Fase 3 · La revisión — el humano

someone builds → Pull request
Pull request → ci/cd checks
Pull request → unit testing
Pull request → static scanning · security
Pull request → human tests the change
Pull request → human reviews the change
Pull request → rollout / deployment
⏱ 15–16.5' · FASE 3: la revisión — la estación MÁS humana de la fábrica. Todo lo construido pasa por el embudo del PR: checks automáticos y luego DOS puertas humanas (probar y revisar). Solo entonces sale a rollout. Aquí es donde el bloque 3 pondrá el foco.
ESTACIÓN 2 · EL SDLC — 4/4

Fase 4 · Operación y bucles

PR → rollout / deployment → PROD
PROD → MONITORING
MONITORING → incidents
incidents → Engineers — vuelta a empezar
LOOP → architecture proposal + sprint planning
LOOP #1 → PR ↔ build
LOOP #2 → users ↔ visión
⏱ 16.5–18' · FASE 4: operación. PROD → MONITORING → incidents → vuelta a Engineers: el ciclo nunca se cierra. Y los 3 bucles del dibujo: planificar (LOOP), construir (LOOP #1) y aprender (LOOP #2). Tiempos del juego: build horas o días · review horas o días.
ESTACIÓN 2 · EL SDLC — FOTO COMPLETA

La foto completa

12 transiciones · 3 bucles · 2 tiempos: build y review, horas o días — así se fabricaba software en 2022.

⏱ 18–19'. La foto completa, ya recorrida fase a fase. Frase de cierre del bloque: «memorizad el DIBUJO, no las herramientas: las herramientas cambian — el ciclo no». Transición a microservicios: «¿y si en vez de una cinta… hay varias?».
ESTACIÓN 2 · EL SDLC

Y si la app se parte en piezas: microservicios

MONOLITO

Una sola pieza: una cinta, un build, un despliegue, un monitor.

Simple — hasta que duele.

MICROSERVICIOS

Piezas pequeñas e independientes: una cinta por servicio — su build, su PR, su despliegue, su monitor.

Se hablan por contratos (APIs) — web ↔ api ↔ base de datos, como la app que visteis en Docker.

La cinta se multiplica: más bucles que orquestar — y más estaciones donde la IA puede entrar.

⏱ 17–19'. BREVE (2'): microservicios = partir la app en piezas con ciclo propio. Conecta con su charla de Docker (web/api/db). Y deja la frase puente al siguiente bloque: «más estaciones = más sitios donde poner un agente… ¿y si los ponemos en todas?».
