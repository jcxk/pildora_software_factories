## Datos clave

### Tabla: "Traditional Development vs. AI Coding Assistants vs. AI Software Factories"

| Factor | Traditional Development | AI Coding Assistant | AI Software Factory |
| --- | --- | --- | --- |
| Task planning | Primarily human-led | Human-led with AI support | Potentially agent-orchestrated |
| Code generation | Developer-written | AI-assisted | Agent-executed within workflows |
| Testing | Developer and CI-driven | AI can suggest tests | Automated tests linked to agent tasks |
| Coordination | Teams and project tools | Individual interactions | Shared orchestration and feedback |
| Deployment | Controlled release process | Usually external to assistant | Integrated with approval gates |
| Human involvement | Across most stages | Direct supervision | Oversight based on task and risk |

### Afirmaciones y tesis principales

- Las fábricas se diferencian de los asistentes por la orquestación, no por el número de agentes: "adding AI agents does not automatically improve the way software is delivered".
- Los feedback loops importan más que la cantidad de agentes.
- La entrega totalmente autónoma de aplicaciones empresariales complejas sigue siendo incierta.
- Los tests no pueden probar corrección: se necesita validación independiente cuando los agentes escriben tanto el código como los tests.
- El rol del desarrollador se desplaza hacia requisitos, arquitectura y verificación; la responsabilidad (accountability) sigue siendo humana.
- El valor está en conectar las actividades, no solo en generar código; el artículo cierra preguntando qué decisiones deberían quedar bajo control humano.
